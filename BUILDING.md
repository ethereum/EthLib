# Building EthLib

Run `lake exe cache get` to fetch Mathlib's published artifacts.
Run `lake build --wfail` to compile EthLib and check every proof.

## Module boundaries

EthLib uses the module system in Lean v4.35.0.
The language rules are in [Source Files and Modules, sections 5.4 and 5.6.1](https://lean-lang.org/doc/reference/4.35.0/Source-Files-and-Modules/).

A definition file has this shape:

```lean
module

public import EthLib.Cryptography.Hash.Sha256

/-! A module docstring. -/

@[expose] public section

-- Definitions and theorems.
```

Public imports preserve the names clients receive through the library roots.
Exposed definitions preserve the reductions that client proofs use.
Theorem proofs stay private, including in an exposed section.
An imports-only file needs no section.
An exposed implementation's helper definitions must also be public.
C exports use plain `public section` because clients execute them through the bindings.

A proof-only import can use plain `import` when it contributes nothing to the public API.
Prefer public equations when reasoning about a dependency.
A targeted `import all` can provide a same-package implementation, or a dependency that permits private imports, to a proof.
Comment the exact definition whose body the proof needs.
Give a public definition an explicit result type when a delayed proof cannot infer it.
Keep compatibility options such as `backward.proofsInPublic` disabled.

The library, proofs, and C exports remain separate Lake libraries.
The declaration checker loads at Lean's `.private` level so it can inspect proof bodies and private helpers.
Its fixtures include module files and a classic root that loads their private information.

Run the module regression after changing these boundaries:

```bash
bash scripts/test_module_system.sh
```

It checks ordinary imports and verifies that changing a private proof preserves the public artifact and skips a downstream build.
Public metadata can still change when source positions move, so a proof edit does not always avoid downstream builds.

## CI cache and timing

CI restores only EthLib's `.lake/build` from successful pushes to `master`.
Mathlib uses its own published cache.
The EthLib cache key includes the operating system, architecture, toolchain, and dependency manifest.
Pull requests read the cache but never publish one.
The manual workflow's `clean_build` input skips the restore.
Before saving, CI deletes generated `*.setup.json` files from the build directory.
These files contain absolute runner paths and are regenerated by Lake.
The cache uses version `v2` so it cannot restore entries saved before this cleanup.

Native objects are platform-specific.
The build therefore does not claim the platform independence used by CompPoly's library-only release archive.

The job summary reports wall time and CPU work for each build and test stage.
Exports are measured before installing the bindings because pip hides a successful build backend's output.
The `ethlib-build-timing` artifact holds the logs, timing records, module tables, and report.
Per-module comparisons use the last samples stored with the restored build.
They compare the same rebuilt modules and retain Lake's reported precision.
Native compilation is included in command timings but excluded from the elaboration table.
Small differences can reflect parallel load or runner noise.

The build pipeline regressions change one export in an isolated Lean project and check that its timing reaches the report.
They also inspect a saved tar archive, restore it, and check that Lake needs no rebuild.
Run them after installing the test dependencies:

```bash
python3 -m unittest discover -s scripts -p 'test_build_pipeline.py'
```

To time a local command:

```bash
export BUILD_TIMING_LOG_DIR=/tmp/ethlib-timing
bash scripts/build_timing_report.sh run library_build "$BUILD_TIMING_LOG_DIR/results.jsonl" -- lake build --wfail EthLib
bash scripts/build_timing_report.sh render "$BUILD_TIMING_LOG_DIR/results.jsonl"
```

The setup follows [ArkLib's migration](https://github.com/Verified-zkEVM/ArkLib/blob/bc367f8d53f603a48c5502e1ad7d39b7b3be725c/docs/wiki/module-system.md) and [VCVio's boundary policy](https://github.com/Verified-zkEVM/VCVio/blob/aae1c9cbd6c00311091d691b74f2d0032d76d9bd/docs/agents/module-system.md).
[CompPoly's cache guide](https://github.com/Verified-zkEVM/CompPoly/blob/9be21b026e43ff9b032113dc9b766d2b17fd6c3c/docs/wiki/build-cache.md) distinguishes dependency caches from release archives.
The ported timing scripts' sources and license are recorded in [BUILD_TIMING_SOURCES.md](scripts/BUILD_TIMING_SOURCES.md).
